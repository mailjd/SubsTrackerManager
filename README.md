# SubsTracker v3.3.20 — 資料保留驗證式升級

這是針對既有 **v3.3.18／v3.3.19、v3 資料結構** 的升級版，不是重新建立帳號／資料庫的初始化包。

**先備份並還原驗證，再分批補遷移；原始資料逐項比對通過才解除維護模式。** 遇到來源衝突、缺失密鑰、錯誤綁定或備份失敗，停止處理，不清庫、不猜測、不覆蓋原記錄。

## 正確入口

閱讀 [安全升級操作指南](SAFE_UPGRADE_3.3.20.md)。GitHub 使用本包 `.github/workflows/deploy.yml`，本機使用 `npm run deploy:safe`。**不要使用舊版 setup、自動建立儲存、直接 wrangler deploy 或手動執行舊遷移 SQL。** 本版 `setup` 僅做只讀預檢和加密備份；直接部署會被保護檢查攔下。

先在原 GitHub 儲存庫 Secrets 新增 **`SUBSTRACKER_BACKUP_PASSWORD`**：至少 16 個字元，建議隨機 32 字元以上，獨立保密保存。既有 Cloudflare Token／Account ID 保留；Worker 必須指向原有實例，而不是新建同名資料庫。

## 本次修正

1. KV、D1 全量聯集與版本核對，補回 v3.3.19 的歷史漏項；舊錯誤完成標記不再阻止修復。
2. 最新有效訂閱與完整原始歷史用於應用備份，不再只匯出較舊的 KV 副本。
3. 升級另外建立加密 **完整儲存備份 `.stbackup`**：原始 KV 值、metadata／expiration、D1 SQL、原設定；解密後在隔離記憶體 SQLite 還原檢查。普通應用 JSON 備份不等同這個完整備份。
4. 從線上既有 Worker 讀取實際 KV namespace ID／D1 database ID，拒絕不一致或模糊的綁定，不建立替代空資料庫。
5. 升級時暫停業務寫入和排程，先等待舊工作結束；歷史每批最多 8 條，具進度檢查及中斷續跑。
6. 提交成功前逐一核對原始 KV key、原表／欄位／每一筆原始列；只允許安全增補。失敗維持維護狀態，保留備份與恢復憑證。

## 保留的功能

v3.3.19 的訂閱與歷史分頁、基礎資料／帳號密碼兩個 Database Tab、公私帳號序號、表格編輯／複製粘貼／模板／篩選、循環續訂與支出儀表板均保留。原始帳號密文、KV 中的加密密鑰／登入設定、模板儲存鍵不重設。非「开会员」的舊記錄可能移到歷史呈現，因此不能用當前頁筆數判斷是否遺失。

## 實測與限制

[更新說明](RELEASE_3.3.20.md) · [驗證報告](VERIFICATION_3.3.20.md) · [部署檢查清單](DEPLOY_CHECKLIST.md)

本機測試使用合成資料、磁碟 KV、SQLite 和 Chromium；没有連接或修改你的正式 Cloudflare 資料。完整 Workers Vitest／型別檢查未在此環境完成，CI 仍保留為部署前必要步驟。安全升級是「資料驗證通過才放行」，不是聲稱任何損壞／缺失的舊資料都能憑空復原。

歴史文件封存在 `release-notes/`；其中舊初始化步驟不得再用作本版升級方法。
