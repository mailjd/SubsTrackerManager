# SubsTracker v3.3.22｜Cloudflare 分階段安全部署

**修正 Cloudflare Git 直連反覆被 require-safe-upgrade.mjs 阻止的問題，保留資料備份與验收，不移除門禁。**

## 立即使用

保留原 Worker、KV／D1 和 Git 連線。Cloudflare → 原 Worker → Settings → Build／Builds：

- Build command：留空。
- Deploy command：`npm run deploy:cloudflare`。
- Builds 機密／變數：原 `CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`、至少16字元的 `SUBSTRACKER_BACKUP_PASSWORD`；核對原 `SUBSTRACKER_WORKER_NAME`，自訂網域另設原 `SUBSTRACKER_WORKER_URL`。

第一次 Build 備份並發布維護版本，顯示 `ST_UPGRADE_WAIT` 和 UTC 的 `readyAfter`。到指定時間之後 **Retry 同一提交**，完成遷移、原資料核對，再開站。通常兩次；不會自動安排下一次。

**只看到 Build 綠色不等於升級完成。必須看到 `ST_UPGRADE_COMPLETE`，且 `/api/upgrade/status` 為3.3.22、maintenance:false。**

完整操作、Token 權限、Build Secrets 與備份下載：**`CLOUDFLARE_SPLIT_DEPLOY_3.3.22.md`**。

## 保留與限制

原始業務記錄、帳號密文、模板、設定、SQL 遷移算法保留；核對實際原 KV／D1 ID，不清庫或重建。這是維護停寫式升級，16分鐘等待未刪除，只移到兩次 Build 之間。原生分段路線需要原 D1，恢復包上限64MiB；更大資料／KV-only 可用原長流程。

本次GitHub工作流改為手動，避免與Cloudflare並行發布。長流程及同版恢復：`SAFE_UPGRADE_3.3.22.md`；實測結果與未驗證部分：`VERIFICATION_3.3.22.md`。舊3.3.20／3.3.21文件僅供歷史查閱，不代表本版還必須Disconnect。
